KDASO:
Knowledge-Data Dual-Driven Automated Skill Optimization for Liability Adjudication Tasks

KDASO evolves a skill library from adjudication data. Neighborhood-conditioned induction turns recently adjudicated neighbours into new skills, execution-aligned refinement rewrites them until the LLM's reasoning trajectory matches expert logic, and context-budgeted routing feeds each case only the skills that can fire.

Abstract

Liability adjudication tasks (e.g., legal charge determination) require analyzing event descriptions against domain-specific skills to determine whether a party should bear liability. While large language models (LLMs) have shown promise in this area by leveraging executable skills for interpretable reasoning, existing approaches face three critical limitations: skill libraries become stale as real-world scenarios dynamically evolve, skill descriptions often suffer from a semantic execution gap where LLMs deviate from intended expert logic, and growing skill collections exceed context budgets, causing critical skill omission.

To address these challenges, we propose Knowledge-Data Dual-Driven Automated Skill Optimization (KDASO), which continuously evolves a skill library through neighborhood-conditioned induction from recent adjudication data, execution-aligned refinement based on LLM trajectory analysis, and context-budgeted routing for scalable skill selection. Experiments across ride-hailing adjudication, legal liability determination and logical reasoning judgment demonstrate that KDASO significantly outperforms current general-purpose and domain-specific baselines. KDASO further achieves an 8.96% improvement when transferring skills to concept-similar scenarios and maintains consistent performance gains through continuous optimization, underscoring the high transferability and stability of the generated skills.

1. Three Failures of Skill-Based Adjudication

Giving an LLM a library of domain skills is attractive because the reasoning stays explicit and auditable. Yet the paradigm fails in three systematic ways: skills cannot be acquired at the speed of the data, cannot be executed as the expert intended, and cannot be deployed at scale inside a finite context window. These are not engineering defects — they are tensions intrinsic to skill-based adjudication.

Coverage under distribution shift

Skill libraries are curated from historical cases and lag behind emerging behaviours such as GPS-spoofing “virtual displacement” fraud. Inducing from a single case captures idiosyncratic noise; inducing from the whole dataset exceeds the context window. A local neighborhood is the only tractable middle ground.

Semantic execution gap

A skill that reads as logic to a human may be executed inconsistently by an LLM: divergent priors and ambiguous operator precedence let the reasoning path drift from the expert's. As Figure 1 of the paper shows, description quality dominates adjudication precision far more than the model does.

Context-budget scalability

The skill omission ratio grows almost linearly with the number of skills in the prompt (R2 = 0.82), and precision decays with it. Attention is selectively allocated, so indiscriminate skill presentation silently discards decision-critical evidence.

2. The KDASO Framework

A skill is a triple s = (Cs, As, Ts) — preconditions that trigger it, adjudication logic that produces the label, and the execution template that structures the reasoning. KDASO treats these three components as the object of optimization rather than the environment of optimization: no parameter of the adjudicator is ever updated, and every improvement is written back into human-readable text.

Neighborhood-Conditioned Skill Induction

Cases are embedded with BGE and scored by cosine similarity. The top-k (k = 4) neighbours of a case form a local chart on the data manifold that supplies sufficient yet non-redundant evidence. The LLM induces a skill from that neighbourhood, which is then validated on real data — an empty support set means a hallucination and the skill is dropped. Conflicting skills are resolved by empirical accuracy or merged by the LLM.

Execution-Aligned Skill Refinement

For each skill, G stochastic trajectories are sampled and compared with the human reference. The misalignment set collects trajectories below threshold τ, and the instability rate ρ(s) flags the skill for rewriting. The LLM diagnoses the lowest-scoring trajectories and rebuilds the skill as an explicit, step-wise execution scaffold, iterating until all trajectories align or the budget is exhausted.

Context-Budgeted Skill Routing

One lightweight XGBoost classifier per skill predicts whether that skill's preconditions hold for a test case. Classifier hits are unioned with direct structural matches, then truncated to the largest subset that fits the context budget, ordered by classifier confidence and match strength — a minimal yet sufficient skill set for every case.

Over a temporal horizon, KDASO maximizes cumulative trajectory alignment while penalizing library growth, so the library stays accurate, compact and adaptable. The loop is stable in practice: with monthly rolling updates the number of newly induced skills and of merges both decline, the average skill length grows mildly, and routing keeps reusing roughly the same number of skills per case as the library expands.

3. Experimental Results

KDASO is evaluated on three real-world domains — five ride-hailing tasks from DiDi, five legal liability tasks from LawBench and LegalBench, and two logical reasoning benchmarks (ReClor, AR-LSAT) — against proprietary LLMs, liable-adjudicated general-purpose algorithms, domain-specific models and open-source general LLMs. All numbers are averaged over three seeds.

4. Transferability, Stability and Deployment

Skills travel to concept-similar tasks

Skills induced on Cancel–Appeal are dropped into Cancel–Passenger-cancel and Cancel–Driver-cancel with no adaptation, and improve all metrics except a comparable O-Precision — a +8.96% average gain, concentrated in bad-faith precision and recall.

Rolling optimization keeps gaining

With monthly rolling updates from July to December 2025, each month's skills are generated from that month's data plus the previous library and evaluated on the next month, giving a steady month-over-month improvement under a drifting distribution.

From research loop to production review

One hour of expert work yields roughly 100 reviewed cases and 5 valid skills. KDASO processes 3,000 cases and proposes 30 candidate skills in the same hour. No skill is deployed autonomously — every candidate passes mandatory manual review before entering the base.

Failure modes are inspectable

Because each decision is traced to a numbered skill, both directions of error can be audited: false exemptions caused by over-generalised evidence clauses, and missed liability caused by over-strict conjunctions. The paper's case study follows one case in each direction.
